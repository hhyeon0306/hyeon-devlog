문제 상황

오브젝트를 다시 사용할 때는 이전 상태가 남지 않아야 합니다. 생성 비용을 줄이는 것만큼, 반환 시점을 명확히 정하는 일이 중요합니다.

  • 누가 반환하는지 책임을 정한다.
  • 다시 사용할 상태를 일관되게 초기화한다.

Return()을 호출할 때 초기화 규칙도 함께 적용합니다.

수명 주기 설계

획득과 반환 사이의 상태를 분리하고, 초기화는 한곳에서 처리합니다.

  1. 사용 가능
  2. 사용 중
  3. 초기화
  4. 사용 가능

정리

풀링은 생성 비용을 줄이는 도구입니다. 안정적인 재사용을 위해서는 상태와 반환 책임도 함께 설계해야 합니다.

이 글과 코드는 화면 검증을 위한 예시입니다. 코드 조각은 중복 반환·용량 제한 등 전체 풀 구현을 생략하고 반환 순서만 보여 줍니다.
